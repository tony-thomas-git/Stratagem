Stratagem — Skills Operational Chart

The current operating model of the Stratagem AI-coding workflow: from raw idea to shipped feature to captured learning, across the manual and unattended execution paths.

Living reference · refreshed 2026-06-30 · supersedes stratagem-testing-workflow.svg (v3) · scope/workflow

What changed since the v3 SVG. v3 showed a single linear PF→CP→PX→AX flow with a human test gate. The system has since grown a seed phase (/ps), an always-on verifier gate (builder≠checker) replacing eyeball-testing, a two-path execution model (manual /phx vs unattended budget-guarded /if), bounded auto-recovery, a memory quick-path, an ADO board rail, and a closed knowledge loop (retros → wiki → corpus-read-first → planning).

Format seam: /ps & /pf author HTML (human reasoning surfaces); /cp re-emits a self-contained .md execution plan (machine-edited by /px /ax /phx /cf, graph-bound). Every /cp task carries an objective Verify: line; decisions are locked up-front via the question-batch.

The execution core — two paths, one verifier gate

After /cp, the plan runs one of two ways. Both drive the same per-task contract — /px → /ax → verify — but differ in who watches and what stops them. The verifier is always on: an executed check plus a separate confirmer (builder ≠ checker).

The knowledge loop — the corpus feeds back into planning

Closing a feature is not the end. Retrospectives distil learnings into the wiki vault; every planning skill then reads that corpus before reaching for the web (CORPUS-READ-FIRST). The system's reasoning surface compounds over time.

The board rail — Azure DevOps (optional)

Board-synced projects get a parallel rail that mirrors plan state onto an ADO Kanban board. Core Stratagem stays board-blind — it only emits headers the stratagem-ado plugin consumes. The never-commit rule holds; linkage happens at PR time.

Operating invariants

Never commit. All changes stay uncommitted for manual review. The /if loop never touches git; its diff lands on a feature branch (HALTs on main/staging). Board linkage happens at PR time, not commit time.
Verifier always-on (builder ≠ checker). Every task is proven by an executed Verify: command plus a separate confirmer instance. There is no opt-out flag; a plan with any task missing Verify: HALTs at /phx's upfront sweep.
Budget is a first-class stop condition. Unattended loops carry a token ceiling (## Budget:, default 750k) that can say "no" independent of the goal — 80% warn, reserve-floor halt, no silent caps.
Literal composition. A skill that chains others invokes them via the real Skill tool — never paraphrased. Sub-skill checklists (e.g. /ax's PICA) only run if the sub-skill actually runs.
Trust-But-Verify within auto-chains. Mid-task L/M decisions auto-proceed and surface in a Decisions Made block; H-complexity decisions STOP and escalate inline. Fleet-wide vault-shape edits always gate.
