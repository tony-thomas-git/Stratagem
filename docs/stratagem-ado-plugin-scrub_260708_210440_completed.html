Feature completion report · 2026-07-09 · plan stratagem-ado-plugin-scrub_260708_210440_plan.md · source PF Stratagem-ADO-Plugin-Scrub_260708_205052_plan.html (kept) · 9/9 tasks · 1 error (EX-001, fixed) · uncommitted

What shipped. The stratagem-ado Claude Code plugin is now portable. It used to bake in one operator's identity, so a second dev couldn't install it. The scrub moved every identity value out of plugin source into a single per-install config home — ${CLAUDE_PLUGIN_DATA}/ado.config.json, beside the existing pat.b64 secret — read by both the MCP launcher shim and the read-side skills. Plugin source now carries zero identity literals; any dev drops in their own config + PAT and it works, no source change.

Architecture — before → after

Identity gets the same per-install treatment as the secret. .mcp.json stops naming the org; the launcher and skills resolve it from the config home.

Before — identity baked into source

.mcp.json → --org intelliscience sp → project ISCI - Consolidated - Kanban, owner tony.thomas@…, intelliscience.visualstudio.com pr → project default + board URL host ss → $env:STRATAGEM_ADO_ORG/OWNER/PROJECT (wrong home) ISCI-Vision/…/settings.local.json → env.STRATAGEM_ADO_*
➜

After — one per-install home

${CLAUDE_PLUGIN_DATA}/ado.config.json
{ org, project, owner } — per-install, outside repo, beside pat.b64 launcher reads org → passes to server
AP-1 shell:true + AP-2 PATH-prepend preserved skills sp · pr · ss → resolve org/project/owner from config; URLs dev.azure.com/<org> .mcp.json + settings.local.json → identity removed

Key achievements

  • One identity home — ado.config.json { org, project, owner }; org reclassified from declarative .mcp.json config → per-install Profile (deliberate evolution of the bundled-mcp-launcher-shim pattern).
  • Launcher self-resolves org from the config (precedence config.org || --org, fail-loud) while preserving AP-1 (shell:true) and AP-2 (execPath PATH-prepend).
  • All three read-side skills (sp/pr/ss) resolve identity from the one home — replacing hardcodes and the $env:STRATAGEM_ADO_* session-env "wrong home".
  • Orphan env removed from ISCI-Vision settings.local.json — confirms the env-promote would have been throwaway.
  • Adversarial verification caught a real leak the enumerated grep would have shipped (EX-001).

Acceptance criteria

  • Plugin is as portable as Core — installable by any dev with their own PAT + config.

Install (per dev)

@{ org = "<your-org>"; project = "<your-default-project>"; owner = "<your-work-email>" } |
  ConvertTo-Json | Out-File -NoNewline -Encoding ascii "$dir\ado.config.json"
