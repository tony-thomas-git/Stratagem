Problem / why this exists

The Stratagem lifecycle is real and load-bearing — /ps → /pf → /cp → /px → /ax → /cf → /rs, with an /ex → /fx recovery loop and the /mpx, /phx, /if variant lanes — but it exists only as prose (the CLAUDE.md "Composition Patterns" block) and as hand-drawn SVGs that no command produces on demand. To see how the pieces relate, you read the config file or open a static diagram. There is no /map.

Two costs follow:

  • Onboarding friction. A person learning Stratagem has no glanceable "here is the whole flow" surface — the mental model is assembled from scattered prose.
  • Drift. The existing diagrams are hand-maintained. When the skill set changes — profile was recently added as the 22nd skill — the SVGs rot silently. This is the same drift class the golden re-baseline and Fleet-Aware rules fight elsewhere; the map should be the one artifact that cannot quietly disagree with the real skill set.

Tell: the request that seeded this listed the commands as /ps/pf/cf/px/ax/ex/fx/cp/rs — out of lifecycle order. Even the framework's author benefits from a canonical rendering.

Shape of the idea

Open questions for /pf

1. Source of truth & drift guard. H — architect's call
Where does the map's content live, and how is it kept honest?
  • (a) Hardcode the ASCII/SVG in map.md; accept manual upkeep (simplest, drifts).
  • (b) Hardcode + golden-test: a compiler test asserts map.md names exactly the shipped lifecycle skill set, so drift fails CI.
  • (c) Generate the map at compile time from a skill manifest (most robust, most machinery).
Lean: (a)+(b) — hardcode for legibility, guard with a golden/compiler test so it can't silently disagree with reality. This is the one H-complexity decision; the rest are L/M.
2. Flavor scope. Ship in all flavors (lifecycle names are flavor-neutral, like profile/um) or coder-only?
Lean: all flavors — one neutral MAP_DESC default, no per-flavor override.
3. The file-creating flag — --html. operator-resolved
The flag that writes a file emits an .html page (preferred), not a bare .svg — styled after the two references: the context-swimlane HTML (the newer favored format) for layout, and stratagem-testing-workflow.svg for the color-legend + emoji language (embedded as inline SVG within the page). ASCII stays the fileless default.
Open only: where it writes — lean docs/ (a caller-named path override), echo the path on completion.
4. Relationship to the existing testing-workflow SVG. Does /map subsume the hand-drawn diagram (become its generator and retire the static file), or stay a lighter command-graph view while the richer testing-discipline diagram — with 👤 human gates, the Feature Status? decision, "no integration test until it works" — lives on separately (perhaps a future --testing view)?
Lean: ship the command-graph view first; leave a --testing superset as a follow-on, and note the static SVG as the thing /map is on track to replace.
5. Command name. Working name is /map; alternatives /flow, /lc, /atlas. Confirm at /pf.
6. Supporting-cast depth. How much beyond the spine does the graph draw — just the core lifecycle, or also /rp /um /pica /crs and the board/notify adapters (/ss /sp /pr)?
Lean: core lifecycle in the main graph; adjacents in a secondary "supporting" band so the spine stays legible.

Non-negotiables

  • Authored in source, not the cache. New skill lives at c:\code\stratagem-core\core\skills\map.md + MAP_DESC in core/vars.yaml; compiled + golden re-baselined. Never hand-edit the plugin cache.
  • Core stays purity-clean. No brand tokens, no absolute home paths in map.md/MAP_DESC (the profile/T15 lesson — the comment naming a token can itself trip the purity lint).
  • Canonical skeleton. Frontmatter (name/description/argument-hint) + {{include: banner-open/close}} + {{include: session-preamble}} + numbered Instructions + Key Principles + Next.
  • The file flag emits HTML, in the house language. --html writes a .html page (preferred over a bare .svg), laid out as a context-swimlane (the newer favored format) and painted in the 5-category color legend + emoji vocabulary from stratagem-testing-workflow.svg — it renders in the established language, it does not invent a new one.
  • Static, silent, fast. No repo reads on the default path; never explain the output — emit the map and stop (um's ethos).
  • The map must not silently drift from the real skill set. A drift guard is in scope, not a nice-to-have — pattern-consistency is canon.
  • ASCII default, HTML opt-in — the operator's stated lean; keeps the hot path lightweight.
