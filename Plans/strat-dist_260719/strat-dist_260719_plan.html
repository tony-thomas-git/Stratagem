1 · Goal

The sg plugin on tt/strat-dist is a hand-derived distributable of the coder flavor, already board-neutralized (commit dd4deee: ADO naming stripped, stratagem-ado removed, notify seam present, stratagem-tavily add-on shipped). It is not yet stack-neutral: the skills still bake in intelliscience's C#/WPF/.NET stack (IVia.*, Castle.Windsor, OnnxRuntime, OpenCV, GoogleTest/MSTest, npm/eslint, .cs/.xaml, native-C++ interop). This feature closes three gaps:

  • Genericize the stack specifics across the skills so the core privileges no language, framework, or test runner (the objective bar: the stack-neutral grep gate reads clean).
  • Add the generic INSTALL.md (the originating question) — a concrete, org-neutral onboarding doc.
  • Document the derivation (docs/DERIVATION.md) so strat-dist is a reproducible transform of the coder flavor, not a black-box one-off.
Decision already locked (this session): NOT a compiler flavor. The compiler (compile.mjs + core/ + templates/) stays untouched in the separate stratagem-core repo. strat-dist is a hand-derived snapshot of the coder plugin. Accepted tradeoff: the snapshot drifts from core; re-deriving is a manual, documented procedure — which is exactly why Gap 3 (DERIVATION) exists.

2b · Grep-invisible hits the gate does NOT catch these — read-scan required

Key finding — the gate is necessary but not sufficient. The pattern matches only its literal tokens. Stack-bound examples that name other libraries pass it clean. Confirmed:
  • stratagem-core-rules.md:282 — the context7 routing bullet privileges React, Next.js, Prisma, MSAL, AG Grid, Tailwind, AWS/Azure SDKs. None of these are in the grep pattern → invisible to the gate, still stack-flavored. Generalize to a category, not a brand list.
  • ex/SKILL.md, ps/SKILL.md — the seed flags "issue-class / diagnostic / exploration phrasing." Zero grep hits; verify by read-scan at build (likely light or no-op — confirm, don't assume).
Implication: Phase 1 must pair the grep gate with a human/agent read-pass for stack-flavored examples.
Second finding — the gate over-reports. The ISCI token matches the word "discipline" case-insensitively (chars i-s-c-i). That alone produces 6 false hits in stratagem-core-rules.md. As written, the gate can never read zero. The plan's verification must anchor the token — ISCI-Vision or \bISCI\b — or the "target zero" bar is unreachable (see §6, D3).

3 · The other two deliverables (net-new)

3a · INSTALL.md (repo root) — the originating question doc

There is no plugins/stratagem-core/INSTALL.md on this branch (it left with the ADO scrub), and readme.md's install section uses an <owner>/stratagem placeholder and stops short of the auto-install mechanics. A dedicated root INSTALL.md documents, concretely:

  • The 3-line marketplace install — claude plugin marketplace add tony-thomas-git/Stratagem → plugin install sg@stratagem → restart. (Note the repo is Stratagem; the marketplace name is stratagem; plugins install as sg@stratagem.)
  • sg is zero-config — defaultEnabled:true, full lifecycle with zero external dependencies.
  • How the workflow self-installs — the SessionStart hook (hooks/hooks.json → sync-autonomy-workflow.sh) copies workflows/autonomy-loop.js into each project's .claude/workflows/ (idempotent, git-repo-only, skip-loud); plus the one-time Workflow(autonomy-loop) grant and the pre-grant .claude/settings.json snippet.
  • The only unique per-install setup — the optional Tavily key at ~/.claude/plugins/data/stratagem-tavily-stratagem/tavily.config.json → { "apiKey": "…" }.
  • Linked from readme.md (trim its install block to point here).

Command structure the doc will carry. The core is a zero-config 3-liner; the Tavily add-on is a separate, optional install that ships OFF (defaultEnabled:false), so it needs install and enable:

# Core — git-backed marketplace, zero external dependencies, defaultEnabled:true
claude plugin marketplace add tony-thomas-git/Stratagem
claude plugin install sg@stratagem
# then restart Claude Code — /help should list /sg:*
# Optional add-on (recommended) — ships DISABLED, so two commands:
claude plugin install stratagem-tavily@stratagem
claude plugin enable  stratagem-tavily@stratagem
# then add your key (free tier at https://app.tavily.com):
#   ~/.claude/plugins/data/stratagem-tavily-stratagem/tavily.config.json  ->  { "apiKey": "..." }

Source material already exists in the vault — [[plugin-marketplace-distribution]], [[workflow-auto-install-hook]], [[bundled-mcp-launcher-shim]] — so this is synthesis, not discovery.

7 · Risks & open edges

  • M Cross-cutting edit surface. ~9 skill files change. Each edit is mechanical (L), but the aggregate touches >5 outputs — treat Phase 1 as one coherent sweep and re-grep after, so no same-family file is missed (cf. the scope-by-category-blindness anti-pattern).
  • M Gate blindness (mitigated). The grep cannot see brand examples or soft phrasing — hence T2's mandatory read-scan. Do not treat a clean T1 as proof of neutrality on its own.
  • L Drift from core. Accepted + documented (DERIVATION). Not solved here by design.
  • L pica semantic loss. Re-authoring away the IVia dimensions must not drop the mechanism (CLAUDE.md-derived scope + PICA-log + report format). Keep mechanics byte-stable; only the dimension list is generic.
  • L Line-number staleness. §2 lines are a snapshot; the build re-greps before editing.
